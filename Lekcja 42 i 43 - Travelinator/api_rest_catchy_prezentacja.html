2. Po co API?

Frontend i backend nie muszą się znać „od środka”

🎨

Frontend

To, co widzi użytkownik: strona, aplikacja, formularz.

🔌

API

Most: przyjmuje zapytania i oddaje odpowiedzi.

🗄️

Backend

Logika, baza danych, autoryzacja, przetwarzanie.

Dzięki API różne aplikacje mogą wymieniać dane w uporządkowany sposób.

API = kontrakt komunikacji
3. HTTP

HTTP to protokół, czyli zasady rozmowy

📜

Protokół mówi „jak”

Kto wysyła zapytanie, w jakiej formie i jak rozumieć odpowiedź.

🧭

API mówi „co”

Jakie zasoby istnieją i co można z nimi zrobić.

Request leci do serwera, a response wraca z wynikiem.

HTTP = język internetu
4. Request

Z czego składa się zapytanie HTTP?

1) URL

/users/1 — adres zasobu

2) Metoda

GET, POST, PUT, DELETE

3) Headers

Dodatkowe info: token, format danych, język.

4) Body

Dane wysyłane np. przy tworzeniu lub edycji.

Najczęściej body = JSON
5. REST

REST = styl projektowania API

REST mówi, jak robić API tak, żeby było proste, przewidywalne i skalowalne.

📦

Zasoby

Myślimy o rzeczach: users, orders, products.

🧾

Reprezentacje

Dane lecą zwykle jako JSON.

🧱

Zasady

REST ma kilka warunków, które porządkują API.

REST API = API zgodne z REST
6. Warunki REST

REST w praktyce: 6 zasad

Klient–serwer

Frontend i backend są niezależne.

Stateless

Każde zapytanie ma komplet informacji.

Cache

Odpowiedzi mogą być zapamiętywane, gdy ma to sens.

Uniform interface

Stały, przewidywalny sposób używania API.

Layered system

Po drodze mogą być warstwy, np. proxy.

Code on demand

Opcjonalnie: serwer może wysłać kod do wykonania.

Najważniejsze: stateless + zasoby + metody HTTP
7. REST API

REST nie robi akcji. REST operuje na zasobach.

❌ mniej REST-owo

/getUser
/createUser
/deleteUser

✅ bardziej REST-owo

GET /users/1
POST /users
DELETE /users/1

Adres mówi czego dotykasz, metoda mówi co z tym robisz.

URL = rzecz, metoda = akcja
8. Metody HTTP

CRUD po ludzku

GET pobierz dane
GET /users

POST utwórz dane
POST /users

PUT zmodyfikuj dane
PUT /users/1

DELETE usuń dane
DELETE /users/1

CRUD: Create, Read, Update, Delete
9. Python requests

requests = proste zapytania HTTP w Pythonie

import requests

url = "https://api.example.com/users"
headers = {"Authorization": "Bearer TOKEN"}
data = {"name": "Alicja", "role": "Python dev"}

response = requests.post(url, json=data, headers=headers)

print(response.status_code)  # np. 201
print(response.json())       # odpowiedź jako słownik/lista

Najczęściej używasz: requests.get(), post(), put(), delete().

requests ogarnia też headers i JSON
10. Kody HTTP

Status code = szybka diagnoza odpowiedzi

1xxinfo: serwer dostał request i coś z nim robi
2xxsukces: np. 200 OK, 201 Created
3xxprzekierowanie: zasób jest gdzie indziej
4xxbłąd klienta: np. 400, 401, 403, 404
5xxbłąd serwera: np. 500, 502, 503

Do zapamiętania: 2xx super, 4xx ty coś źle wysłałaś, 5xx serwer ma problem.

Status mówi, co poszło dobrze/źle
11. Mini checklista

Jak czytać dowolne REST API?

  • Jaki jest URL zasobu?
  • Jaką mam użyć metodę HTTP?
  • Czy potrzebuję headers, np. tokenu?
  • Czy wysyłam body, np. JSON?
  • Jaki status code dostałam i co oznacza?
