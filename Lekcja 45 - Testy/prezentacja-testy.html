Testy, czyli co definiuje dobry program

Jak sprawdzić, czy kod naprawdę działa — unittest vs pytest

Co definiuje dobry program?

1. Działa poprawnie

Dla konkretnych danych zwraca konkretny, oczekiwany wynik.

2. Da się zmieniać

Po poprawce szybko widzimy, czy przypadkiem czegoś nie zepsuliśmy.

3. Jest sprawdzalny

Nie trzeba wierzyć „na oko” — można uruchomić test i dostać jasną odpowiedź.

Test = definicja poprawnego działania

Dobry test mówi:
„dla tego wejścia oczekuję takiego wyniku”

Myślimy jak tester

  • Co funkcja dostaje na wejściu?
  • Co powinna zwrócić?
  • Co może pójść źle?
  • Jak sprawdzić to automatycznie?

Mini teoria: rodzaje testów

Dzisiaj skupiamy się na testach jednostkowych, ale warto znać większy obraz.

Jednostkowe

Sprawdzają jedną funkcję, metodę albo klasę. Szybkie i najlepsze na start.

Integracyjne

Sprawdzają, czy kilka części programu dobrze działa razem.

Systemowe

Sprawdzają aplikację jako całość, tak jak używałby jej użytkownik.

Regresji

Chronią przed sytuacją: „poprawiliśmy jedno, zepsuliśmy drugie”.

Wydajnościowe

Sprawdzają, czy program działa wystarczająco szybko.

Bezpieczeństwa

Szukają miejsc, przez które ktoś mógłby program źle wykorzystać.

Jak czytać wynik testu?

PASS / OK

Test przeszedł. Program zachował się tak, jak oczekiwaliśmy.

FAIL

Test nie przeszedł. To nie koniec świata — to wskazówka, gdzie szukać błędu.

Dobry test mówi nie tylko, że coś jest źle, ale też co dokładnie się nie zgadza.

unittest — wersja „szkolna”

Co trzeba zapamiętać?

  • wbudowany w Pythona
  • testy piszemy w klasie
  • dobry do nauki klasycznego stylu testów
  • ma dużo gotowych metod sprawdzających

Słowa-klucze

unittest TestCase test_ assertEqual assertTrue assertFalse main()

pytest — krócej i wygodniej

Słowa-klucze

pytest assert not -v parametrize capsys pip install

Co trzeba zapamiętać?

  • trzeba zainstalować: pip install pytest
  • test może być zwykłą funkcją
  • wystarczy zwykłe assert
  • -v pokazuje więcej informacji

unittest vs pytest

unittest

  • bez instalacji
  • bardziej formalny zapis
  • dużo metod typu assertEqual, assertTrue
  • dobry do poznania klasycznego stylu testów

pytest

  • krótszy kod
  • czytelne assert
  • łatwe testowanie wielu przypadków
  • często wygodniejszy w praktyce

Najważniejsze asserty w unittest

Assert to pytanie do programu: „czy wynik jest taki, jak oczekuję?”

assertEqual(a, b)sprawdza, czy a == b
assertNotEqual(a, b)sprawdza, czy a != b
assertTrue(x)sprawdza, czy x jest prawdziwe
assertFalse(x)sprawdza, czy x jest fałszywe
assertIn(a, lista)sprawdza, czy element jest w kolekcji
assertIsNone(x)sprawdza, czy wynik to None
assertGreater(a, b)sprawdza, czy a > b
assertRaises(Błąd)sprawdza, czy pojawia się wyjątek

Co będziemy testować?

Palindromczy słowo czytane od tyłu jest takie samo?
Trójkątczy z boków da się zbudować trójkąt?
Dzielenieco się stanie przy dzieleniu przez 0?
Sortowanieczy lista jest posortowana po długości?
Liczby pierwszeczy liczba ma tylko dwa dzielniki?
Średniaco zwrócić dla pustej listy i błędnych danych?

Praktyczne triki

Testuj przypadki graniczne

Nie tylko „ładne” dane. Sprawdź też 0, pustą listę, zły typ danych, dzielenie przez 0.

Nazwy mają pomagać

test_valid_triangle mówi więcej niż test1.

Jeden test = jeden pomysł

Łatwiej znaleźć błąd, kiedy test sprawdza konkretną rzecz.

Najpierw spodziewany wynik

Zanim uruchomisz test, odpowiedz: „co funkcja powinna zwrócić?”

Mini workflow na lekcji

1piszemy funkcję
2piszemy test
3uruchamiamy
4czytamy błąd
5poprawiamy kod

Dobry programista nie boi się czerwonego testu — bo czerwony test pokazuje, co naprawić.
